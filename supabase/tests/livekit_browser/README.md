# LM isolated provider browser rehearsal

This workflow starts a pinned disposable OSS LiveKit server on runner loopback and renders the real LiveMeetingMedia component with two distinct provider identities. Browser-generated test camera/microphone signals travel through actual WebRTC. Success requires decoded remote video frames, increasing inbound RTP bytes, stable remote audio elements and actual provider room/track observations. Screen capture uses only the disposable Xvfb display through Chromium's picker. No user content, hosted tokens, cloud recording or hosted SQL changes occur. No application dependency or production route is added.

The test fixture bypasses hosted admission only to isolate transport; its locally signed identities are not authenticated Convay user accounts. Provider removal/rejoin and deletion test provider operations, not app host authority, SQL quorum or authenticated meeting closure. Screen capture may fail on runner/browser limitations; missing evidence is a failing check, never PASS. Hosted two-company admission, real user devices, network interruption, recording/transcription entitlements, authoritative attendance and the 42 requirements/12 journeys are distinct mandatory gates. No paid activation authorized.
