## Concurrency preparation
Existing tenant admin and verified invitation-claim writers take different advisory locks. Candidate takes a transaction-scoped SHARE table lock NOWAIT on tenant_memberships before membership checks and idempotent receipt reads, so absent membership rows cannot appear between guard and write. Reject non-READ-COMMITTED assignment transactions and historical handover membership before replay. Standard INSERT/UPDATE/DELETE writers conflict automatically; no change to their implementation or shared helper. This deliberately coarse staged guard may transiently reject assignments during unrelated membership writes; evaluate contention, retry UX, lock ordering and whether to replace with coordinated per-identity protocol in restored environment before approval. Concurrent membership-first and assignment-first tests run in isolated PG17 sessions; committed fixture only exists inside disposable container. No assumption of native Auth or production readiness.

### Profile authority concurrency
Staged assignment now locks actor, target and optional handover profiles in UUID order FOR UPDATE NOWAIT after membership lock and repeats root/permission checks before any replay or write. Profile status/role writers therefore serialize with the assignment; contention fails closed and is retryable. Tests cover actor status-first receipt denial, handover suspension-first denial, transfer-first profile writer exclusion and exact durable audit counts. This deliberately conservative profile locking can serialize root operations; evaluate contention and shared writer ordering in restored infrastructure. No hosted root change or native Auth/session-revocation proof.
