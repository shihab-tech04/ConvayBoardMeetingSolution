# Free-tier local verification
This workflow starts an **unlinked, disposable** Supabase stack on the existing public-repository CI runner. No hosted credentials, real user records, paid branches, hosted migration or deployment are used. The first migration binds an already-confirmed identity, so the local-only test replaces that one UUID/email predicate with a newly created synthetic Auth account. The source SQL itself is not changed.

The script replays checked-in migrations, then applies the specified staged candidates in the disposable environment. It exercises actual GoTrue password sign-in and PostgREST JWT-based company/draft lifecycle authorization, with real tenant creation, A/B denial, receipt replay and the legacy fallback reproduction/correction. The role fixture is trusted local seed data, not a certification of the user onboarding or invitation UI.

A native custom-format pg_dump of synthetic app/Auth/Storage metadata is generated, inspected and restored into a new database in the same disposable local cluster. The test compares all selected table row counts/content digests and five security catalogs, including RLS policies, function definitions, ownership and normalized grants. Cluster roles and compatible extension dependencies are supplied by the same disposable cluster. This is **not** a restore of hosted production data, real user credentials, Storage object bytes, external providers or a complete platform/cluster recovery; the existing native production recovery gate remains. No local credentials or archive are uploaded. Do not add production secrets to this PR-triggered workflow. The actual hosted backup needs an authorized private local runner and securely supplied DB connection; retain encrypted off-GitHub backup plus restore evidence.
